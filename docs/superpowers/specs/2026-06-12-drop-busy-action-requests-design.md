# DesktopCat 忙碌动作请求丢弃设计

日期：2026-06-12

## 背景

当前运行时保证非 `idle` 动作不会被普通动作打断，但会把忙碌期间收到的
动作请求加入 `pending_actions`。连续点击或连续选择菜单动作时，这些请求会
在当前动作结束后依次执行，导致后来真正想触发的动作长时间无法响应。

本次修改保留“动作不可被普通请求打断”，但取消动作排队。猫猫忙碌期间
收到的普通交互请求立即失效，不在当前动作结束后补播。

## 目标行为

一次需要动作的交互被视为一个完整的“动作 + 气泡”请求：

- 猫猫空闲时，动作立即开始，对应气泡同时显示。
- 猫猫正在执行非 `idle` 动作时，请求立即被拒绝。
- 被拒绝请求的动作和气泡都不显示，也不保存到任何待执行列表。
- 当前动作自然结束后回到既定状态，此后到达的新请求可以正常执行。
- 忙碌期间被拒绝的旧请求不会在猫猫空闲后重新出现。

示例：第一次摸摸头启动 `clicked` 后，再连续点击四次，后四次完全失效。
第一次 `clicked` 结束后新触发“开心一下”，猫猫立即执行 `happy`；之前四次
点击不会补播。

## 运行时设计

### 动作接收

`RigDesktopCatApp.set_action()` 继续返回 `bool`：

- `True`：动作已立即启动。
- `False`：猫猫忙碌，请求已丢弃。

删除动作队列相关状态和逻辑：

- `MAX_PENDING_ACTIONS`
- `self.pending_actions`
- `queue_action()`
- `finish_current_action()` 中启动下一项队列动作的分支

`finish_current_action()` 只按照现有 `ACTION_CHAIN` 回到下一个自然状态，不再
执行忙碌期间收到的请求。

当前 `on_press()` 会先记录 `drag_start`，再请求 `clicked`；旧实现因此把第一
次点击也判定为忙碌，并依赖动作队列延后启动。删除队列时必须同步修正这个
入口：

- 猫猫处于 `idle` 时，鼠标按下可以立即启动 `clicked`。
- 后续真的发生拖动时，`drag` 仍可立即接管。
- 猫猫正在执行其他非 `idle` 动作时，鼠标按下不会启动或排队 `clicked`。

`action_can_start_immediately()` 不再用“鼠标已按下”本身拒绝普通动作；是否
正在拖拽由当前 `drag` 动作和拖拽事件负责。`resetting_position` 仍会拒绝普通
请求。

### 动作与气泡原子性

所有会同时触发动作和气泡的入口必须先尝试启动动作，只有
`set_action(...) is True` 时才提交气泡：

- 左键摸摸头
- 开心、卖萌、打招呼、睡觉
- 向左走、向右走和自主散步
- 礼物互动
- 自动陪伴语料

这样即使 `RigSpeechBubble` 仍有自己的消息队列，被拒绝的动作请求也不会把
对应文案送入气泡系统。

`happy` 只有在动作成功启动后，才保留本次随机方向和起点。忙碌时拒绝
`happy` 不应改变正在播放动作所依赖的方向或位置状态。

### 自动陪伴语料

自动陪伴语料在忙碌期间触发时整条放弃，不延迟补播：

- 不启动消息指定的动作。
- 不显示或排队消息气泡。
- 本轮定时检查结束，等待下一次正常检查。

消息冷却时间只应在消息真正展示后记录。被忙碌状态拒绝的消息不能被标记
为已展示，否则会在没有展示的情况下进入冷却。

### 保留的强制例外

以下行为不是普通动作请求，继续允许立即介入：

- 拖拽：鼠标拖动时立即进入 `drag`，松开后强制回到 `idle`。
- 睡眠唤醒：点击已进入 `sleep` 的猫猫时可用 `force=True` 立即播放 `wake`。
- 回到屏幕角落：作为位置救援操作，继续强制执行 `return_home`。
- 首次启动：欢迎展示继续强制播放 `wave`。
- 全部语料视觉巡演：测试工具继续使用 `force=True` 精确展示指定动作。

点击 `sleep_in` 期间不强制唤醒的现有边界保持不变；普通请求仍会被拒绝。

### 无动作气泡

固定时间提醒等不附带动作的气泡不受动作忙碌状态影响。保留
`RigSpeechBubble.pending_messages`，因为它解决的是气泡互相覆盖，与本次删除
的动作请求队列职责不同。

## 测试策略

更新 `tests/test_rig_preview.py`：

- 非 `idle` 动作期间的新动作返回 `False`，当前动作和帧不变。
- 运行时不存在动作排队状态。
- 当前动作结束后按 `ACTION_CHAIN` 返回自然状态，不启动旧请求。
- 动作结束后到达的新请求返回 `True` 并立即启动。

更新交互与消息测试：

- 连续摸摸头时，忙碌期间的点击不显示气泡。
- 空闲时第一次鼠标按下立即启动 `clicked`，不依赖释放或后续 idle 动作。
- 鼠标从点击转为拖动时，`drag` 仍立即接管。
- 菜单动作被拒绝时，对应气泡不显示。
- 自动陪伴消息被拒绝时不显示气泡，也不记录冷却。
- 自动陪伴消息成功启动时才显示并记录冷却。
- `happy` 被拒绝时不改动当前方向和跳跃起点。
- 拖拽、睡眠唤醒、回到屏幕角落和首次启动的强制行为保持不变。

## 非目标

- 不允许普通动作中途打断另一个普通动作。
- 不保留“最后一次请求”或单槽缓冲。
- 不删除气泡系统自身的队列。
- 不改变动作帧、时长、FPS、随机 idle 行为或文案内容。
- 不修改 `raw/wake_*` 实验素材。
