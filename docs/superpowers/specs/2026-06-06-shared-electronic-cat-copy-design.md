# DesktopCat “共同养电子小猫呆呆”语料改造设计

日期：2026-06-06

## 目标

将 DesktopCat 的叙事从“桌面小猫代表粑粑陪伴麻麻”调整为：

> 呆呆是麻麻和粑粑共同养的一只电子小猫。现在两人异地、暂时不能一起养真实小猫，所以先让电子呆呆在桌面上陪麻麻生活。

呆呆不是粑粑的化身，也不以传声筒作为主要功能。它应像一只属于两个人的小猫，有自己的幼猫口吻和陪伴感，同时偶尔自然提到粑粑，形成“我们一起养它”的家庭感。

## 语气设计

采用混合口吻：

- 日常提醒：自然、温柔、不过度卖萌。
- 点击、卖萌、首次启动、特殊日子：可以更像幼猫。
- 自称混合使用“呆呆”和“我”：
  - 首次启动、卖萌、特殊日子优先使用“呆呆”。
  - 简短互动可使用“我”，避免每句话重复名字。
- 大部分文案围绕呆呆陪麻麻生活。
- 粑粑只在少数合适场景自然出现，不让呆呆重新变成粑粑的替身。

## 默认身份

- 小猫名字：`呆呆`
- 她的称呼：`麻麻`
- 你的称呼：`粑粑`

这三个称呼都允许通过配置修改。

## 配置模型

在 `CatConfig` 中新增：

- `mama_nickname: str = "麻麻"`
- `papa_nickname: str = "粑粑"`

保留旧字段：

- `partner_nickname`

兼容规则：

1. 新配置文件同时写入 `mama_nickname`、`papa_nickname`。
2. 读取旧配置时，如果没有 `mama_nickname`，使用旧 `partner_nickname` 作为麻麻称呼。
3. 如果两个字段都没有或类型错误，回退为 `麻麻`。
4. `papa_nickname` 缺失或类型错误时回退为 `粑粑`。
5. `partner_nickname` 暂不删除，继续保存以兼容旧版本，但运行文案不再以它作为主要字段。

## 动态占位符

所有离线陪伴语料支持：

- `{pet_name}`
- `{mama_nickname}`
- `{papa_nickname}`

渲染发生在气泡显示前，使用当前配置值。

错误处理：

- 已知占位符正常替换。
- 未知占位符保留原样，不导致程序崩溃。
- 普通文本和不含占位符的旧自定义语料继续正常显示。

## 运行文案调整

### 基础互动

基础点击、开心、卖萌、打招呼、睡觉、醒来、散步文案改成呆呆自己的口吻。文案不应暗示“我是粑粑”或“我代替粑粑”。

### 首次启动

首次欢迎语表达：

- 呆呆正式来到麻麻桌面。
- 呆呆是麻麻和粑粑共同养的电子小猫。
- 语句保持简短，不做长篇背景说明。

### 右键互动

- 删除菜单项 `我想他了`。
- 删除对应 `MISS_PARTNER_MESSAGES` 随机回复列表和运行方法。
- 将 `今天辛苦啦` 改为 `麻麻辛苦啦`。
- 回复由呆呆直接安慰麻麻，动作继续使用 `cute`。

### 定时提醒

午饭、晚饭、睡觉、深夜提醒统一称呼麻麻。

建议语气：

- 呆呆负责轻轻提醒。
- 少数提醒可以提到粑粑，但不应每条都出现粑粑。
- 保留当前时间窗口、重复间隔和关闭按钮行为，本次只改文案。

### 低打扰模式与位置

功能行为不变，只调整文案为呆呆口吻。

## 离线陪伴语料

更新 `partner_default.json`：

- 日常时间段语料以呆呆陪麻麻生活为主。
- 备用语料不再使用“我一直站在你这边”“看到小猫就当我抱你”等粑粑化身表达。
- 少数 evening、bedtime、special_day 文案可以自然提到粑粑。
- 优先使用占位符，避免把称呼写死。

类别和当前时间窗口保持不变：

- `morning`: 07:00-11:30
- `lunch`: 11:30-13:30
- `afternoon`: 13:30-18:00
- `evening`: 18:00-22:30
- `bedtime`: 22:30-01:30
- `late_night`: 01:30-05:00
- `special_day`: 匹配 `month_day` 时优先
- `miss_you`、`busy_support`、`comfort`、`encouragement`: 时间段语料不可用时备用

其中 `miss_you` 类别可以保留，但语义改为呆呆想念麻麻/粑粑或一家人的团聚感，不对应已删除的右键菜单。
